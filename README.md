# 沿途 · 骑行天气

导入 GPX，查看骑行路线、附近区域和预计到达时的天气。

## 使用

1. 粘贴顽鹿或行者公开路书分享链接导入，或上传 WGS84 坐标的 GPX，也可载入环滆湖示例。
2. 设置出发时间（北京时间）、骑行均速、总休息时间和采样间距。
3. 点击“查询沿途天气”，在天气卡片与地图之间查看各点详情。

支持温度、体感温度、降雨概率、降水量、风速、阵风及按局部行进方向估算的迎风/顺风分量。最多采样 18 个点。

## 2026-10-26 功能更新

本次发布包含路线天气着色、日出日落提示、本机收藏，以及行者公开路书导入。

- 路线天气着色：晴为橙色，阴／多云为灰色，降雨为蓝色，雾为白色并配深色描边，雪为淡紫色，雷暴为紫红色。未查询或数据缺失时使用绿色虚线。颜色按各采样点预计经过时刻的天气代码确定，以相邻采样点的里程中点划分，不代表实际雨区边界。点击路线可定位对应天气卡片。修改出发计划会清除旧颜色。
- 日出日落：使用同一天气接口的逐日 sunrise、sunset 数据，结合各采样点的预计到达时间估算沿途日出日落事件。在行程内或行程开始前／结束后 30 分钟内时，插入时间线并添加地图标记；无相关事件时不显示。支持跨日骑行。位置、剩余行程均依赖现有恒定均速及休息均摊假设，天文时间不代表天气或地形造成的实际光照。
- 本机收藏：使用 IndexedDB 保存完整轨迹、路线名称、来源链接，以及均速、休息和采样设置；最多 50 条，每条不超过 150,000 点。相同轨迹重复保存会更新名称和设置。载入收藏时保留当前出发时间，天气重新查询。支持删除、撤销最近一次删除、JSON 完整备份及合并导入；导入先验证全部路线后一次性写入，相同轨迹跳过，不覆盖已有收藏。
- 本机收藏仅在同一浏览器配置和同一网站来源（协议、主机名、端口）下可用。关闭页面后通常保留，但清除网站数据、结束无痕浏览或浏览器回收空间可能导致丢失。没有登录、服务端收藏或跨设备自动同步。导出的备份包含完整坐标，可手动转移。

新增计算与数据验证检查：`node features-check.mjs`。浏览器测试覆盖保存／重命名／去重、刷新持久性、完整轨迹恢复、备份导入导出、无效导入原子性、六种天气颜色、雾天描边、日出日落触发与清理、窄屏布局、接口失败状态。浏览器分支测试使用隔离环境中的合成预报，不作为实况依据；真实接口联调单独验证。

## 地图提供商

地图左上角可以切换提供商：

- OpenTopoMap：备用地形图，不需要 Key，保留来源署名；服务在海外，国内网络仍需实测。
- OpenStreetMap：保留为备用。无底图成功加载时，会在超时或连续失败后尝试一次备用源，不循环重试。
- 天地图矢量／影像：默认使用矢量底图和中文注记，可切换影像。`map-config.js` 保存网站所有者提供的公开浏览器端配置；Key 需要限制到两个发布域名。此 Key 会在网页和瓦片请求中可见，不适用于服务端秘密。地图设置仍支持临时填写其他 Key，刷新后恢复网站默认值。

轨迹与天气查询沿用 GPX 地理坐标，天地图使用 `_w` 墨卡托瓦片；未接入需要 GCJ-02 或 BD-09 偏移的高德、百度瓦片。实际授权取决于天地图控制台的 Key 类型与域名白名单。

本次移除了 Google Fonts 请求，字体使用设备已有字体。地图、天气、地名是三个独立外部服务，更换地图或部署平台不会自动解决其他接口的网络问题。

## Cloudflare 部署

当前已通过 Cloudflare Workers Builds 连接本仓库的 main 分支。构建命令为 `npm run build`，由 `build.mjs` 将网页、必要的前端脚本（含 `favorites.js`、`xingzhe.js`）、`map-config.js` 和 assets 复制到 public 目录，再发布该目录；避免将 node_modules 作为地图资源上传。后续 main 提交自动发布。旧的 Pages 手动部署步骤见 [CLOUDFLARE.md](./CLOUDFLARE.md)。

## 本地运行与检查

在本目录使用已有 Node.js：`node dev-server.mjs`（或 `npm run dev`），然后访问 `http://127.0.0.1:8765`。该本机服务同时提供网页和顽鹿／行者导入接口，直接复用仓库内 `services/route-import/` 的代码，无需额外目录或安装依赖。它仅监听本机并检查 Host、Origin、请求类型和大小，导入最多同时处理两个任务，不保存原始路线到服务器。

只查看静态页面仍可使用已有 Python：`python -m http.server 8765`，但静态服务不提供本机路书导入接口。

使用 Node.js 检查核心计算：`node check.mjs`，不需要安装依赖。

地图逻辑测试：`node maps-check.mjs`，检查 Key 校验与隔离、底图和注记顺序、缩放限制、仅一次自动备用、清除 Key。

## 数据与范围

- 天气：[Open-Meteo](https://open-meteo.com/)，其免费 API 限个人非商业用途，需遵守官方调用额度与署名要求。
- 地名：[Photon](https://photon.komoot.io/) / OpenStreetMap，公共服务仅适合合理请求量，可能限流或不可用。
- 地图：默认 [天地图](https://www.tianditu.gov.cn/)，备用 [OpenTopoMap](https://opentopomap.org/about)（地图署名 OpenStreetMap、SRTM、OpenTopoMap，CC-BY-SA），备用 [OpenStreetMap contributors](https://www.openstreetmap.org/copyright)，可选 [天地图](https://www.tianditu.gov.cn/)。地图组件 Leaflet 1.9.4 的许可见 assets/LEAFLET-LICENSE.txt。
- GPX 在浏览器解析，不上传完整文件；查询天气和地名时向相应服务发送采样点坐标。天气与地名缓存仅在本次页面内存中；用户主动收藏的路线另外保存在浏览器 IndexedDB 中。
- 区域是采样点附近地名，不是严格的行政边界相交结果，可能遗漏短距离跨界。预报按最近整点匹配，天气与到达时刻均有误差。
- 此版本支持未来 15 天内的骑行计划，不提供历史天气。所有输入和显示时间均为北京时间。
- 示例含 2,352 个轨迹点，几何长度约 127.32 km（平台标注 126.812 km），没有高程。原坐标按顽鹿编辑器逻辑推断为 BD-09 后转为 WGS84，未实地核验。


## 顽鹿链接导入

本机验收服务通过同源 `/api/import/onelap` 调用现有转换逻辑；正式站点继续使用下述 Cloudflare 接口。

页面支持 myroute 分享路线和 route 数字 ID 公开路书。调用独立 Cloudflare Worker `https://onelap-gpx.changanxiaoxiang.workers.dev/api/convert`，接收 GPX 后复用本地 GPX 解析、地图、采样和天气查询。默认在导入成功后自动查询当前出发计划的天气，可取消勾选。保留上传、拖入 GPX、下载转换文件、示例、地图选择和“现在”按钮。

转换服务访问失败、限流或数据无效时不替换当前路书。导入期间禁止重复操作和并发修改路线；自动查询使用现有出发计划。源坐标默认 BD-09 为既有样本推断，提供手动坐标选择，不能保证所有路线原坐标一致。

转换接口依赖 workers.dev 的网络可达性，网页可打开不等于转换服务可达。本地 GPX 导入不依赖转换后端。天气、地名服务仍单独联网查询。测试：`node onelap-check.mjs`。

## 行者链接导入

支持 `https://www.imxingzhe.com/routes/<数字ID>/` 分享链接，忽略 `from=app` 等分享参数。与顽鹿共用入口，自动识别平台；顽鹿坐标选项仅对顽鹿显示。导入后继续使用原有地图、天气查询、路线着色、日出日落、本机收藏和 GPX 下载。

2026-10-26 已优先检查直连：本机浏览器标准 `fetch(cors)`、`credentials:omit` 对官方 GPX 和公开详情接口都不能读取响应。另行 HTTP 检查显示 GPX 接口（含末尾斜杠）返回 401，公开详情返回 200；对本机、GitHub Pages 和当前 Cloudflare 网站 Origin 都没有 `Access-Control-Allow-Origin`，只有 `Access-Control-Allow-Credentials:true`，不足以允许浏览器跨域读取。两个正式网站 Origin 仅做响应头检查，没有修改或在正式站点注入测试脚本。

本机方案读取分享页无需登录即可使用的公开详情，再根据当前分享页绘制逻辑读取公开 JSON（新格式）或公开 version2 轨迹数据（兼容入口），解码为 GPX，不调用要求登录的官方 GPX 下载接口。请求不携带用户 Cookie、Authorization 或登录信息，遇到 401／403 会停止。固定详情 API，动态文件地址必须匹配行者官方 OSS 域名及详情返回的同一 UUID 路径；不跟随重定向，限制响应大小、点数和请求时间。动态签名文件地址只在本次处理使用，不写入收藏或业务日志。

样本 `5701846`：“河海金坛—河海遗址”，1,634 点、2 段、3 个途经点、1,634 个原有高程值。生成 GPX 的几何长度约 102.454 km，行者标注 102.568 km；保留源分段，不为段间间隔补直线。坐标按当前网页逻辑读取为 WGS84，尚未实地核验。生成的是公开轨迹的 GPX 表达，并非官方登录导出的原文件；不承诺恢复官方导出中的其他扩展字段。下载保留原高程，现有地图与本机收藏沿用经纬度轨迹，未增加高程展示。

本机使用 `/api/import/xingzhe`；正式站点使用现有转换 Worker 的 `/api/xingzhe`。后端源码、许可与配置一同保存在 `services/route-import/` 中，与静态网站分开部署。发布需先更新后端并验证，再发布网站；线上验证记录见 `RELEASE.md`。

检查：`node xingzhe-check.mjs`；后端 GPX 解码、域名与文件校验、无凭证请求、错误与超时；浏览器检查覆盖真实样本导入和 GPX 下载、收藏恢复、无效导入保留旧路线与天气、窄屏及顽鹿回归。确定性天气分支使用合成数据，实际本机页面另行完成真实天气联调。
